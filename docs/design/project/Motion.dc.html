Design system · Motion

Springs, not durations

Modeled on iOS / SwiftUI: every movement is a damped spring defined by response (how fast) and damping fraction (how much it settles vs. overshoots). Springs are interruptible — a menu closed mid-open reverses from its current position and velocity, never jumps. Press any demo; press again mid-flight.

Chrome (menus, sheets, sidebar, tabs) never visibly overshoots. Bounce is reserved for moments of physical cause: a toast arriving, a dropped file landing, a success check. Distances stay short (≤ 8 px travel for popovers) so even a 350 ms spring feels instant.

Motion for React (motion.dev)
// src/lib/motion.ts
export const spring = {
  snappy: { type: "spring", stiffness: 632, damping: 50.3, mass: 1 },
  smooth: { type: "spring", stiffness: 322, damping: 33.0, mass: 1 },
  bouncy: { type: "spring", stiffness: 224, damping: 23.3, mass: 1 },
} as const;

// SwiftUI equivalents
// snappy  .spring(response: 0.25, dampingFraction: 1.00)
// smooth  .spring(response: 0.35, dampingFraction: 0.92)
// bouncy  .spring(response: 0.42, dampingFraction: 0.78)

<motion.div
  initial={{ opacity: 0, scale: 0.96, y: -4 }}
  animate={{ opacity: 1, scale: 1, y: 0 }}
  exit={{ opacity: 0, scale: 0.98 }}
  transition={spring.snappy} />

// wrap app in <MotionConfig reducedMotion="user">

CSS linear() can't retarget velocity — use it only for enter/exit. Anything interruptible or gesture-driven (sheets, sidebar, tabs, drag) goes through Motion.
